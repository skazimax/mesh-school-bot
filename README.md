# Telegram-бот для МЭШ

Семейный Telegram-бот для электронного дневника «Московская электронная школа».
Показывает домашние задания и оценки всех детей родительской учётной записи,
формирует компактные табличные отчёты и отправляет их в общий канал или группу.

Python 3.12+, aiogram 3, HTTPX, SQLite. Для работы достаточно одного процесса;
Docker, Redis и отдельный сервер базы данных не требуются.

## Возможности

- Выбор одного ребёнка или всех детей; выбор сохраняется отдельно для каждого чата.
- ДЗ на завтра, с завтрашнего дня до конца недели и на следующую неделю.
- Оценки за неделю и месяц с официальным средним МЭШ за текущий учебный период.
- Динамика среднего относительно предыдущей недели: `↑`, `↓`, `→`;
  при отсутствии сравнения — `—`. Разные триместры не сравниваются.
- Один автоотчёт на ребёнка в день: дневной с понедельника по четверг,
  недельный по пятницам, месячный — в последний будний день месяца.
- Управление кнопками в личном чате, канале, группе и супергруппе.
- Автоматическое продление авторизации, локальный кэш и ежедневные резервные копии.

Пример отчёта на вымышленных данных:

```text
👤 Анна
Неделя 14.09–18.09
📊 Триместр 01.09–30.11
Предмет      Оценки Среднее    До⑤
──────────── ───── ────────── ───
Математика   5 4 5 4,62 ↑0,12  0
Русский язык 4 5   4,40 ↓0,10  3
История      —     5,00 →     0

До⑤: пятёрки веса 1 до 4,50.
Ориентир, не итоговая оценка.
```

## Быстрый запуск

Нужны Python 3.12 или новее, родительская учётная запись mos.ru с доступом к МЭШ
и токен Telegram-бота, созданного через [@BotFather](https://t.me/BotFather).

Из корня репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
cp .env.example .env
chmod 600 .env
```

В `.env` заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_CHAT_IDS`.
Вторая переменная — личные Telegram ID пользователей, которым разрешено
настраивать бота и обращаться к нему в личке, через запятую.
ID общего канала или группы задаётся отдельно в `TELEGRAM_REPORT_CHAT_ID`.

Выполните первичную авторизацию МЭШ в интерактивном терминале:

```bash
python -m tools.mesh prepare-login
python -m tools.mesh login
python -m tools.mesh profile
```

`prepare-login` загружает закреплённые данные регистрации мобильного клиента
и проверяет SHA256. Затем `login` запрашивает логин mos.ru, пароль и при
необходимости SMS-код. Пароль и код не сохраняются; авторизация записывается
в `.secrets/auth.json`. Подробности интеграции: [docs/api.md](docs/api.md).

Запустите бот:

```bash
python -m app.main
```

Откройте своего бота в Telegram и нажмите `/start`.
Для постоянной работы на Linux используйте [инструкцию systemd](docs/operations.md).

## Канал или группа для отчётов

Добавьте бота администратором общего чата. В канале разрешите публикацию сообщений.
Если бота добавляет пользователь из `TELEGRAM_ALLOWED_CHAT_IDS`, чат подключается
автоматически и получает панель управления.

Если бот уже добавлен:

- В группе или супергруппе отправьте `/start` от разрешённого пользователя.
- В канале опубликуйте `/start`; разрешённый пользователь должен быть его администратором.
- Либо отправьте боту в личку `/channel -100…` с ID общего чата.
- Для канала также можно переслать боту в личку любой пост из него.

Автоматические отчёты идут только в один подключённый общий чат.
До подключения автоматических отправок нет. По умолчанию выбраны все дети;
сохранённый выбор общего чата определяет содержимое автоотчётов.
Выбор ребёнка через кнопки общего чата и в личке применяется отдельно
к личным запросам пользователя, не меняя выбор других участников.

Все разрешённые пользователи имеют одинаковый доступ ко всей семье.
Кнопками в общем чате могут пользоваться его участники; отдельных ролей по детям нет.
Команды из группы и кнопки общего чата присылают ручные ответы в личку
вызвавшему пользователю. Сначала каждый участник должен открыть личный чат
с ботом и нажать «Старт». Если личка недоступна, отчёт в группу не публикуется;
для команды появляется одна подсказка в день, для кнопки — всплывающее уведомление.
Участники подключённого общего чата также могут работать с ботом непосредственно
в личке; членство проверяется. Команда, опубликованная от имени канала,
отвечает в канале: Telegram не передаёт боту личность автора такого поста.
Под отчётами и ДЗ кнопки не прикрепляются, а постоянная клавиатура в личке
скрывается. В общем чате остаётся отдельная панель управления, созданная при
подключении; при необходимости её можно закрепить. Выбор ребёнка открывается
отдельной командой `/children`.
Обычную групповую переписку бот игнорирует.

## Команды

| Команда | Назначение |
|---|---|
| `/start` | Меню и помощь |
| `/children` | Выбрать ребёнка или всех детей |
| `/tomorrow` | ДЗ на следующий календарный день |
| `/hw_week` | ДЗ с завтрашнего дня по воскресенье текущей недели |
| `/hw_next` | ДЗ на следующий понедельник–воскресенье |
| `/week` | Оценки за текущую неделю |
| `/month` | Оценки за текущий месяц |
| `/channel` | Подключить общий чат; в личной переписке |
| `/status` | Состояние синхронизации и подключения |

В общих чатах можно использовать команды с именем бота: `/start@имя_бота`.

## Настройки

Полный шаблон: [.env.example](.env.example).

Отчёты по оценкам поддерживают два формата: `REPORT_FORMAT=text` (исходные
текстовые таблицы, по умолчанию) и `REPORT_FORMAT=image` (компактная картинка
для каждого ребёнка). Параметр применяется к ручным и автоматическим дневным,
недельным и месячным отчётам. ДЗ остаются текстовыми при любом выборе.
Для переключения измените `.env` и перезапустите бота. Формат виден в `/status`.

Картинки рисуются локально из данных МЭШ, без внешнего сервиса генерации.
На Linux установите шрифт `fonts-dejavu-core` (`sudo apt install fonts-dejavu-core`);
на macOS и Windows используется Arial. Собственный шрифт с кириллицей можно
указать в `REPORT_FONT_PATH` (путь к `.ttf`). Длинные названия и списки оценок
переносятся, высота изображения подстраивается под число предметов.
Уже начатый автоотчёт после переключения завершится в сохранённом формате:
переотправки доставленных частей не будет.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `REPORT_FORMAT` | `text` | `text` — таблицы текстом, `image` — картинки оценок |
| `REPORT_FONT_PATH` | Автоматически | TrueType-шрифт с поддержкой кириллицы |
| `TELEGRAM_BOT_TOKEN` | — | Токен своего Telegram-бота |
| `TELEGRAM_ALLOWED_CHAT_IDS` | — | Положительные личные ID разрешённых пользователей |
| `TELEGRAM_REPORT_CHAT_ID` | пусто | Отрицательный ID общего чата; можно подключить через бота |
| `TELEGRAM_PROXY` | пусто | HTTP/SOCKS5-прокси для Telegram |
| `MESH_AUTH_FILE` | `.secrets/auth.json` | Файл авторизации МЭШ |
| `MESH_PROFILE_ID` | пусто | Родительский профиль; обычно определяется автоматически |
| `MESH_PROXY` | пусто | HTTP/SOCKS-прокси для МЭШ |
| `MESH_CA_BUNDLE` | пусто | Собственный доверенный CA bundle |
| `MESH_HTTP_TIMEOUT` | `20` | Таймаут HTTP-запросов МЭШ, в секундах |
| `DATABASE_PATH` | `data/bot.db` | SQLite с кэшем и состоянием отправок |
| `TZ` | `Europe/Moscow` | Часовой пояс |
| `DAILY_REPORT_TIME` | `19:00` | Время дневного отчёта |
| `WORKER_ONLY` | `false` | Только синхронизация и backup, без Telegram |

Привязка общего чата через бота хранится в SQLite и имеет приоритет над
`TELEGRAM_REPORT_CHAT_ID`. `MESH_LOGIN`, `MESH_STUDENT_ID` и
`MESH_REGISTRATION_FILE` — дополнительные настройки CLI авторизации и диагностики.
Рабочий бот автоматически получает всех детей.

Прокси для МЭШ и Telegram настраиваются независимо; системные proxy-переменные
автоматически не используются. TLS-проверка остаётся включённой.

## Расписание и расчёты

Синхронизация — каждые 30 минут с 07:00 до 21:00 в заданном часовом поясе.
Дневной отчёт — с понедельника по четверг в `DAILY_REPORT_TIME` и только для
детей с новыми оценками за текущий день. В пятницу вместо него отправляется
один недельный отчёт на ребёнка. В последний будний день календарного месяца
месячный отчёт заменяет дневной или недельный. Первоначальный импорт не создаёт
уведомления о новых оценках. Новизна оценки определяется по времени появления
в кэше, недельные и месячные списки — по дате урока.

Среднее в таблице берётся из МЭШ за текущий учебный период, а не вычисляется
из оценок за неделю. Снимок для динамики сохраняется при успешном ручном
недельном запросе или после доставки автоматического недельного отчёта.
Используется предыдущая календарная неделя того же учебного периода;
пропущенная неделя не заменяется более ранним снимком.

Колонка «До⑤» показывает минимальное число дополнительных пятёрок для достижения
среднего `FINAL_FIVE_THRESHOLD` (по умолчанию 4,50). Учитываются числовые оценки
всего текущего триместра и их веса; вес каждой будущей пятёрки задаётся
`FINAL_FIVE_WEIGHT` (по умолчанию 1). Например, при оценках 4 и 4 веса 1 нужны
две пятёрки веса 1. Ноль означает, что порог уже достигнут; «—» — нет периода,
оценок или расчёт не совпадает со средним МЭШ в пределах округления.
Расчёт предполагает, что других новых оценок не будет. Это ориентир:
правила выставления итоговой оценки и порог уточняйте в школе.

При недоступности МЭШ ручные запросы показывают сохранённые данные с предупреждением,
автоотчёты ждут успешной синхронизации. Прогресс отправки сохраняется после каждой части.

## Данные и обслуживание

`.env`, `.secrets/`, `data/`, резервные копии, виртуальное окружение и кэши
исключены из Git. Файлы авторизации и SQLite создаются с правами `0600`.
Используйте бота с собственной учётной записью и в общих чатах,
участникам которых вы готовы показывать семейный дневник.

```bash
python -m tools.runtime status
python -m tools.runtime reports
python -m tools.runtime backup
```

`status` выводит состояние и количества записей; `reports` — только длины отчётов,
без личного содержимого и отправки сообщений. `backup` создаёт согласованную копию SQLite.
Ежедневные резервные копии хранятся 14 дней. Восстановление и обновление:
[docs/operations.md](docs/operations.md).

## Разработка

```bash
python -m pip install -e '.[dev]'
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m mypy
```

Тесты используют вымышленные данные и имитацию HTTP/Telegram; они не требуют
реальной учётной записи и ничего не отправляют.

Структура: `app/` — бот и сервисы, `tools/` — авторизация и диагностика,
`tests/` — регрессионные проверки, `systemd/` — шаблон Linux-сервиса,
`docs/` — интеграция и эксплуатация.

## Ограничения

Это неофициальная интеграция, не связанная с разработчиками МЭШ.
Изменения API или авторизации mos.ru могут потребовать обновления клиента.
CAPTCHA и неизвестные шаги входа автоматически не обрабатываются.
При отзыве доступа может понадобиться повторный интерактивный вход.
Отсутствие задания в ответе API не гарантирует, что учитель ничего не назначил.
При аварии между отправкой сообщения и записью результата возможен повтор одной части отчёта.
