# Интеграция с МЭШ

Бот использует неофициальный mobile API МЭШ. Нормализованный клиент находится
в `app/mesh/normalized.py`; Telegram-обработчики работают через сервисы и SQLite.

## Авторизация

Первичный вход выполняется через `python -m tools.mesh login`:

1. Регистрация динамического OAuth-клиента mos.ru.
2. PKCE-вход с интерактивным вводом пароля и при необходимости SMS-кода.
3. Обмен mos.ru access token на mesh access token.
4. Активация через `dnevnik.mos.ru/acl/api/users/profile_info`.

Пароль и SMS-код не сохраняются. Данные динамического клиента и токены хранятся
в приватном JSON. В логах и стандартном выводе токены не показываются.
Новый refresh token сохраняется до дальнейшего обмена, чтобы не потерять ротацию.

`prepare-login` извлекает metadata регистрации из закреплённой версии
[mesh-diary](https://github.com/voenniy/mesh-diary/tree/319c44ff25a156dacd3afdf2773959db31ca29dc),
проверяет SHA256 и сохраняет `.secrets/registration.json`. Исходный JS не выполняется,
metadata не включается в репозиторий. Источник и checksum заданы в `tools/mesh.py`.

Клиент автоматически продлевает доступ перед истечением токена и делает одну
попытку refresh/replay после HTTP 401. Основной grant — `client_credentials`;
для известных отказов предусмотрен ограниченный fallback на `refresh_token`.
Работоспособность продления зависит от состояния устройства и учётной записи;
при отзыве доступа нужен новый вход. Параллельные запросы и refresh сериализованы.

## Данные и идентификаторы

Mobile-префикс: `https://school.mos.ru/api/family/mobile/v1`.

| Endpoint | Данные |
|---|---|
| `/profile` | Родительский профиль и дети |
| `/marks` | Оценки за диапазон дат |
| `/subject_marks` | Средние и границы учебных периодов |
| `/homeworks/short` | Домашние задания за диапазон дат |

Диапазоны передаются как `from`/`to`, родительский профиль — в `Profile-Id`.
`profile_id` владельца токена и `student_id` ребёнка — разные идентификаторы.
Границы учебного периода берутся из `periods[].start_iso/end_iso`, среднее —
из значения текущего периода. Если период определить нельзя, годовое среднее
не подставляется. Сравнение динамики включает ребёнка, предмет и тот же период.

Оценки хранятся по составному ключу ребёнок + ID оценки. Изменения оценки
обновляют запись, сохраняя время первого появления. Первоначальная история
помечается отдельно и не создаёт дневные уведомления. Удаление оценки по её
отсутствию в ответе API не определяется. ДЗ заменяются в кэше только после
успешного получения полного запрошенного диапазона.

## Диагностика

```bash
python -m tools.mesh profile
python -m tools.mesh marks --from YYYY-MM-DD --to YYYY-MM-DD --student-id STUDENT_ID
python -m tools.mesh averages --student-id STUDENT_ID
python -m tools.mesh homework --student-id STUDENT_ID
```

Если детей несколько, диагностические команды требуют явный `--student-id`
или `MESH_STUDENT_ID`; рабочий бот получает всех детей автоматически.
`--show-data` выводит персональное содержимое только для локального сравнения
с дневником. Не публикуйте такой вывод.

Для обезличенной проверки всех детей и корректности фильтрации дат:

```bash
python -m tools.mesh_verify --from YYYY-MM-DD --to YYYY-MM-DD --narrow YYYY-MM-DD
```

`mesh_verify` выводит количества и результаты сверки; пустые ответы сами по себе
не подтверждают интеграцию. Диагностический CLI не обновляет токены после 401
автоматически. Не запускайте ручной login/refresh или API-диагностику одновременно
с сервисом: остановите его и запустите снова после проверки.

МЭШ HTTP-клиент использует явные настройки прокси и CA bundle, `trust_env=False`
и обязательную проверку TLS. GET-запросы имеют ограниченные повторные попытки;
запросы пароля, SMS и OAuth POST автоматически не повторяются.
